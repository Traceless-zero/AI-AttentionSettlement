# aggsettle — 确定性结算器

> 单文件、零依赖、标准库。
> 它不调用模型。它做一件事：**把"从长文里数数"从模型手里拿回来。**

---

## 0. 它是什么位置上的东西

同一个诊断（**保真带稀缺 + 失败静默**）在本周结晶出两条**互不替代**的响应：

| | 救援视图 | **结算器** |
|---|---|---|
| 路线 | 修**读取**——把内容搬进保真带，模型仍然读 | 绕**读取**——可形式化的任务不让模型读 |
| 适用 | 语义任务（"哪条最重要"） | 查一行 / 数数 / 求和 / 极值 |
| 失败模式 | 检索落空，可审计 | `NOT_FOUND`，可审计 |
| 训练成本 | 0 | 0 |

**它不是"救援视图"的替代品，是同一张决策表里"可形式化"那个分支的代码化身。**

而且它是视图研究的**极限情况**：A 试验量出最小充分视图 = 证据行本身（105 字符，10/10）；2×2 量出视图修枚举（1/5 → 3/5 @ 3,127 字符）。结算器的"视图"就是值列表本身——几十字节，**视图尺寸的下确界**。

---

## 1. 为什么会有它

2026-10-21 的实测（两模型、多长度、多几何）：

| 任务 | 模型读数 | 失败形态 |
|---|---|---|
| 单事实（问某条记录的值） | **20/20** | — |
| 计数 / 求和 / 极值 | **0/6 – 1/5** | **枚举不全**：5 条只看得到 1 条 |
| 问不存在的实体 | 4/5 与 0/5 拒答 | 不拒答时**替换成同类型真实值**（89% 同型） |

失败不是算错。32K 那次求和回复是 `1303 + 6429 + 6268 + 7082 = 21082`——四项加对了，漏了第五个。

所以：

> **聚合不该交给模型，该交给能穷举的代码。**
> **拒答也不该交给模型——它会安一个同类型的真值上去。**

## 2. 它怎么工作

```
语料 ──规范化──▶ 切行 ──▶ 三元组抽取（实体/数值/单位）
                                 │
问题 ──路由──▶ lookup | count | range | sum | max | min
                                 │
                    ┌────────────┴────────────┐
              识别为可形式化              识别不了
                    │                        │
          代码聚合 + 证据行          UNROUTED（不猜，交上层）
                    │
             证据校验通过？
              ├─ 是 → 输出答案
              └─ 否 → EVIDENCE_MISMATCH（按失败处理）
```

### 三条硬纪律

1. **认不出的问法一律拒答**（`UNROUTED`），**永不落入猜测型 handler**。
   *这条是补出来的*：早期版本把 `between 2000 and 6000` 漏路由，掉进 `search` 返回了错误答案——**路由器在系统上层重建了它在模型里诊断出的那种静默失败**。现已改为拒答。
2. **答案必须能从证据行复现**（`verify()`），否则 `EVIDENCE_MISMATCH`。
   证据不是装饰：`count` 校验条数、`sum` 校验加总、`lookup/max/min` 校验值出现在证据文本里。
3. **找不到实体 → `NOT_FOUND`**，绝不替换。

## 3. 自检与对照

```
python aggsettle.py --self-test      →  9/9
```

同一批题、同一语料，模型 vs 结算器：

| 语料 | 模型 | 结算器 |
|---|---|---|
| 5 针（`probe_hard5`） | 1/5 | **5/5** |
| 20 针（`probe_hard`） | 1/5 | **5/5** |

### ⚠ 这个对照有选择效应（必须与数字同读）

语料是我造的、题是我出的、正则是照这些题写的。**题目全部落在结算器的语法内，而模型面对的是开放题面。**

所以诚实表述不是"代码在聚合上胜过模型"，而是：

> **对可形式化的聚合，失败模式被消除，而不是被战胜。**

`9/9` 是自洽性证明，**不是泛化证明**。

## 4. 摄取层：两个必须分开报的数

```bash
python capture_rate.py
```

### 实体捕获率（20 个实体）

| 损伤类型 | 捕获 | 说明 |
|---|---|---|
| 干净 | **20/20** | — |
| 空格分隔 `NX 7001` | **20/20** | 可逆，规范化修复 |
| OCR 混淆 `NX-7OO1` | **20/20** | 可逆（0↔O） |
| 长横线 `NX–7001` | **20/20** | 可逆 |
| **末位丢失 `NX-700`** | **0/20** | **不可逆** |
| **改成描述 `the main archive`** | **0/20** | **不可逆** |

> **分界线不在"脏"，在"可逆"。** 形态破坏能救，信息丢失救不了。

### 问题路由率

8 个问句中 **6 个可路由**，另 2 个（"which archive is the most important"、"list everything"）**正确判为 `UNROUTED`**。

## 5. 它不新在哪，新在哪

**不新**：「数学交给代码」这件事 PAL / Toolformer / text-to-SQL 在 2022 年就说完了。README 不把这句当卖点。

**新的两处：**

1. **路由表是从自己的失败测量导出的**——不是先设计再找场景，是先测出「任务类型 × 干扰结构」的悬崖，再把掉下悬崖的那部分形式化；
2. **失败可审计是一等设计约束**——`NOT_FOUND` / `UNROUTED` / `EVIDENCE_MISMATCH` 三个出口都是显式的。模型那 31/31 的"替换"在这条路径上**不是变好了，是没有发生的入口**。

---

## 6. 边界（说出来，不藏）

| 能做 | 不能做 |
|---|---|
| 结构化/半结构化事实的聚合 | 语义题（"哪条最重要"） |
| 实体名可被形态规则捕获 | 无固定形态的指代（"那个服务"） |
| 数值 + 单位可枚举 | 图片表格里的数、需要跨表连接 |

---

## 7. 第二身份：仪器

它每个答案自带证据行，所以可以回灌进评测管线：

- **answer key 生成**：新语料的真值与证据由代码产出，人工只抽检；
- **判分者审计**：判分侧也会同型采样（`n_win` 事故），判分同样该有 verbatim 证据链。

**demo 与仪器，一鱼两吃。**

## 8. 用法

```bash
python aggsettle.py --corpus 文档.txt --ask "How many archives hold more than 7000 entries?"
python aggsettle.py --corpus 文档.txt --facts        # 看抽到了什么
python aggsettle.py --self-test                     # 回归
python demo_vs_model.py                             # 模型 vs 结算器 对照表
python capture_rate.py                              # 摄取层体检
```

输出示例：

```json
{
  "kind": "count",
  "n_facts": 20,
  "answer": "6",
  "refused": false,
  "evidence": ["NX-7003=9536", "NX-7014=8292", "..."]
}
```
