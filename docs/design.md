# 系统设计：AI-AttentionSettlement —— 窗口内动态注意力结算层

> 设计口径 · 2026-10-24 ｜ 前身：《大模型窗口内动态注意力机制构想》v3.3（2026-10-19 定稿）
> 本文件是 v3.3 的公开压缩版 + 2026-10 对话期新增理论；实验读数见《研究报告》。

**Abstract (EN).** An external, training-free settlement layer over the context window: per query, spans are scored and a compact **view** is materialized and re-prefilled; the original stays as a lossless, pointer-addressable **sediment layer**. Positioning (verified against 2024–2026 literature): per-query selection and materialized views are a crowded space; the vacant intersection is **pointers + lossless sediment + drill-down re-read** — "everyone changes what the model reads this turn; nobody guarantees it can go back and re-read when the choice was wrong."

---

## 0. 一句话与定位

> **每次提问时，以该提问为锚点对上下文做一次全局相关性结算，选出高分 span 物化为二级视图；模型只读视图；原文无损沉在沉积层，可按指针回读。**

一句话差异化（对照 15+ 近邻后）：

> **别人都在改"模型这次读什么"，只有本设计保证"读错了还能按指针回去重读"。**
> 承重三件套 = 换场（视图 re-prefill）+ 在场（检索只需 gold 进窗，不需精排）+ 无损（原文永不被覆盖）。

## 0·补 构想源起与演化

**最初设想**：把这套系统**放进 AI 模型内部**——以用户最新输入为基底，对其余上下文做注意力权重打分，聚合出一个容量为模型「注意力舒适区」的二级上下文窗口，作为模型内部的注意力结算视图。

**实验后的两处修正**：

1. 打分粒度 token 级被证伪——拆句即死（句子拼贴 0/3，连续切片 3/3），单位必须是 **span / 回合**；
2. 「放进模型内部」拆开看只有**判断层**成立（§1）：「读什么、何时该回去重读」可以且应该被训练进模型；
   但视图的**物化**（re-prefill 是编排动作）与**无损可回读的保证**（存储+指针+审计，权重给不了承诺）
   物理上只能在模型外。

**最终定位：模型内部（习得的读取判断）＋ 外部（视图物化与保证基建）的协作分层。**
本仓库实现并度量的是外部那一半；内部那一半的规格（L* 标定协议、任务悬崖电池、视图预算）恰由外部测得。

## 1. 三层拆解与「内外之辨」

「这套东西应该做进模型还是外挂？」是个假二分。拆三层：

| 层 | 内容 | 归宿 |
|---|---|---|
| **判断层** | 读什么、何时结算、何时回读 | 应该进模型，且正在进（agent 训练把"分片读、记笔记、回头重读"焊进轨迹；Know-When-to-Stop / SEAL / retrieval-heads 线是前哨） |
| **执行层** | 驻留 KV、re-prefill、换场 | 永远在服务栈——模型无法对自己 re-prefill，这是编排动作 |
| **保证层** | 无损沉积、指针账本、审计回放 | 永远在模型外——**"无损可回溯"是运行时的承诺，不是权重能给出的能力**；训练得再好的模型只能"表现可靠"，不能"承诺不出错" |

类比：虚拟内存没有做进 CPU 核，它是 MMU + 页表 + 磁盘的横向分层。**本设计是 OS 层，不是更大的 CPU。** 外部实现的双重意义：外部先做出证据和语义，平台再吸收（RAG→长上下文、压缩→context editing、缓存→prompt caching 的历史路径）；且治理/审计/跨厂商中立这个位置，物理上只存在于模型之外。

## 2. 路由：四个出口

```
Q（最新用户输入）
 ├─ 0. 预算内 no-op        语料 < 舒适预算（200K token）→ 整份透传；
 │                          续说类（"继续"）→ 目标本在尾部高注意力区，跳过
 ├─ 1. 集中式选择           实体问句 → lookup 视图；语义问句 → search 视图
 │                          （BM25 粗筛 → CE 精排 → span/回合级视图 + 坐标指针）
 └─ 2. 弥散式扫掠（未建）   gather 全量视图 / 分片 loop（见 §5.3，预注册未实施）
```

no-op 的定性：这是**注意力管理工程，不是检索**——目标已在天然高注意力区时，造视图是多此一举；预算内整份透传是正确行为而非失职。

## 3. 打分器

两级流水：**BM25 粗筛（标准库实现，0 依赖）→ CE 精排（BGE-reranker-v2-m3，可选层）**。

- 成本（CPU 实测）：BM25 全量免费；CE ≈50ms/对，20 对 1.3s；全量 5,400 句 ≈270s 不可用 → 必须两级。
- **CE 的 512 token 硬截断**：超长块给全量与前 512 token 打分完全相同（实测差 0.0）——分数只反映块头。块级只配当 BM25 粗筛单位，不配进 CE。
- 单位由**语料结构**决定：有分节标记→块；散文→句；对话→整回合绝不拆（拼贴 0/3，连续切片 3/3）。
- 诚实边界：CE 是判别式相关性（"相关吗"），非生成式重要性（"有用吗"）；打分器是全局单点故障，系统天花板 = 打分器天花板。

## 4. 视图

| 模式 | 触发 | 视图 | 实测 |
|---|---|---|---|
| turns（默认） | 对话回合格式 | 相关整回合、原文序拼接 | 1.43M token / 5,000 回合 → 1.1s，12/12；预算悬崖 r≈0.25 |
| lookup | 问句含具体实体 | 含该实体的最小窗口 | 61–78 字符；缺实体 → 空视图交上层拒答 |
| gather | 聚合意图 | **全量同型实例（不是 top-k）** | 20 事实 → 1.2–1.7K 字符，整个聚合集装进 2K 预算 |
| search | 其余 | 句级 BM25（CE 精排） | 200K 字符 k8s → 32 字符视图 |

预算口径：**token**（默认 200K = 注意力舒适区上界；中文 1.5 字/tok、其他 4 字/tok 估算）；装不下整单元就跳过并显式标注 `incomplete`，**绝不拆块**。每个 span 携带回沉积层的行号指针——这是"下钻"的接口。

## 5. 选择与压缩：分工轴与「压缩降级」

### 5.1 三 regime（按相关性分布）

| regime | 相关性形态 | 正确响应 | 证据 |
|---|---|---|---|
| 集中（针式） | 答案落在少数几句 | **选择** | 单事实 20/20；105 字符最小充分视图 |
| 弥散·可形式化 | 所有实例相关、可提值 | **gather 全量视图**（枚举材料备齐；模型能否自行完成聚合 = §8 判定实验） | 1.2K 视图装下 20 事实 |
| 弥散·不可形式化 | 每段都弱相关（综合/主题） | **迭代（loop）**，见 5.3 | 聚簇×视图 1/5→3/5（视图修枚举不修算术） |

### 5.2 理论主张：压缩降级为派生缓存

> **压缩可以从权威源的位置上退位，降级为派生缓存；权威源（沉积层）永远无损，压缩件永远可从它再生。**（git 类比：diff/summary 随便生成，对象库一个字节不丢。）

破坏性压缩的原罪不是"压"这个操作，而是"压完覆盖原件"。外部破坏性压缩只活在两个正当生态位：摊销经济（一次压缩多次复用、缓存友好）与无回读场景（流式/边缘/无代理能力的下游）；以及一个错误生态位——在弥散任务上被当成唯一选项（5.3 的 loop 是替代项）。

### 5.3 loop attention（预注册设计，未实施）

弥散不可形式化任务的迭代解：**分片 → 短窗高保真区读 → CoT 留笔记（带指针）→ 下一片 → 收尾聚合**。理论根基：CoT 本就是注意力分配的序列化展开（v3.3 §2），loop 是把它**跨 re-prefill 接力**；下钻是它的窄形态（救援路径），扫掠是它的宽形态（正常路径）。

三条诚实代价（均可测，构成三臂电池的判读轴）：错误累积（笔记有损且逐轮复利）；问题降尺度重演（笔记自己长大 → 需对笔记再结算，几何收敛条件=每级压缩比够高）；覆盖率记账（恰好需要坐标指针——④指针是 loop 的地基，不是装饰）。

## 6. 成本模型：三方账本与交叉点

每轮边际成本（设缓存读价 = 全价 × d，典型 d=0.1–0.5）：

| 方案 | 前缀何时变 | 每轮成本 |
|---|---|---|
| 携带生长（不压缩） | 永不变（追加式） | d × C，C 持续涨，最终超窗 |
| 压缩携带 | 压缩事件时全灭 | d × C′ + 重置摊销（C′=压缩后短上下文） |
| **每轮重组视图** | 每轮都变 | **1.0 × V**（语料本体从不进 prompt） |

**交叉点：V < d × C 时，每轮重选反而更便宜。** 例（d=0.1，C=130K）：携带 ≈13K 等效/轮；2K 针式视图 = 2K/轮（更便宜）；32K 视图 = 32K/轮（更贵）。此式修正 v3.3 §9 的"多轮场景结构性成本优势为负"——不是一刀切负，是交叉点问题。携带模式的隐藏脆弱点：缓存 TTL（典型 5 分钟）过期即退化全价重灌。

**计费层的演化方向（2026-10 观察）**：prompt caching 本身是 2024 年才出现的新计费 primitive；Gemini 已有按存储时间计费的上下文缓存（按"驻留+被读"计费而非按请求重发计费）；长上下文分档定价在惩罚大窗口。真正的下一块积木是**随机访问的驻留 KV**（语料 prefill 一次按存储计费、每问只对选中片段付注意费）——它对厂商算力也是双赢（少注意=少算）。若平台做成"托管沉积层"，外挂层的席位上移到跨厂商中立 + 可审计。

## 8. 未测部件与预注册协议

**下钻救援臂（最优先，系统新颖性的承重梁）**：视图答错/拒答时按指针回沉积层扩取重读再答。判据（预注册）：触发率、救援成功率、救援后命中提升。预注册出口：触发率 <5% 且手动下钻无增益 → "唯一新颖点空转"成立，转反转纲领（失效边界测量本身可发表——"策展式阅读在什么条件下劣于全上下文阅读"）。靶场：k8s T2（锚定串号主场，视图最易漏 gold 的场景）+ 119 回合对话语料。

**loop 三臂电池**（§5.3）：弥散不可形式化任务（128K 语料主题综合），全档直读 / 分片 loop / 外部压缩后读；判质量 × 成本 × 错误传播。

**NSA 待测假设**（§7）。**冷启动对照 / T3 杀手格 / L3 意图级**：设计已成文预注册，未跑。

## 9. 边界与风险

1. **打分器单点故障**：系统天花板 = 打分器天花板；针式分布 BM25 recall@5=100%，agent 真实问题分布（模糊/多跳/价值回溯性）未验证。
2. **平台吸收时钟**：1–2 年窗口期（v3.3 附录 D）。模型厂商做进模型（citation recall 类）、平台做成托管沉积层，都会压缩外挂空间；长期席位=跨厂商中立 + 审计回放——这个位置物理上只在模型外。
3. **loop 的三条代价**（§5.3）未测即未知。
4. **规模三约束**（v3.3 附录 B 继承）：打分器成为新瓶颈、query-conditioned 与索引召回的张力、极端长度下身份渐变为分层记忆系统（对手变成成熟 RAG 栈）。
